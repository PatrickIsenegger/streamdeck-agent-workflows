# Discoverability Notes

GitHub Trending is not a checklist you can force. Treat it as a possible side effect of a useful, timely, easy-to-share project.

## What helps

### Clear positioning

A good first sentence should answer:

- What is this?
- Who is it for?
- What can someone do with it in five minutes?

### Topics

GitHub topics help people find repositories by subject area. Use lowercase, hyphenated topics and keep them specific enough to be useful.

Suggested topics for this repository:

```text
stream-deck
streamdeck
codex
claude-code
ai-agents
automation
productivity
icon-system
design-system
workflow-automation
macos
windows
linux
```

### A real README

A good README should include:

- concise value proposition
- screenshot or graphic
- quick start
- project map
- safety boundaries
- contribution invitation
- license summary

### Community health files

Useful public repos should include:

- `CONTRIBUTING.md`
- `CODE_OF_CONDUCT.md`
- `SECURITY.md`
- issue templates
- clear licensing

### Shareable graphics

A good social preview image helps when the repository URL is shared in chat, social media, or link previews. GitHub supports repository social preview images in repository settings.

Recommended size: `1280 x 640`.

This repo includes SVG diagrams in `graphics/`. A future maintainer can create a raster social preview from the same visual language.

## What does not help

- inflated claims
- fake stars
- private exports disguised as examples
- overbroad topics
- screenshots that leak personal setup details
- one huge repo with no clear first task

## Launch checklist

- Add GitHub topics.
- Add a social preview image.
- Share the companion article.
- Open 2-3 small starter issues for contributors.
- Ask Windows and Linux users for verification notes.
- Keep the first issues narrow and practical.
